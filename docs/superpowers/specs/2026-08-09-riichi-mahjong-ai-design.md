# 自制立直麻将 AI — 设计文档

- 日期:2026-08-09
- 状态:已获用户批准
- 项目仓库:`/root/riichi-ai`

## 1. 背景与目标

自制一个立直麻将(リーチ麻雀)AI。参照系:NAGA(Dwango,专有)、Suphx(微软,专有+论文)、LuckyJ(腾讯,专有)、Mortal(Equim,开源 AGPL)。

**核心结论(可行性调研)**:当前顶级 AI 几乎不做博弈树搜索,靠"海量高段位人类牌谱 + 监督/离线 RL 训练出超强策略网络"。LuckyJ 是唯一公开使用不完全信息搜索的。单张 RTX 5070 Ti(16GB)足以复刻 Mortal 级别训练;**瓶颈是数据规模、工程管线与迭代时间,而非 GPU**。复现 Suphx/LuckyJ 级别(十段、吊打职业)不现实——需要公司级算力(kanachan 作者估算 Suphx 级自对弈在单张 RTX 3090 上需约 5 年)。

### 目标(已与用户确认)

1. **主目标**:离线训练自己的立直麻将 AI,追求强度。现实目标 = 稳定打赢 akochan(约天凤七段相当);冲刺目标 = 接近 Mortal(约天凤八~九段)。
2. **远期延伸**:天凤特上卓接入(官方允许 AI 账号在特上卓及以下对战)。
3. **后置**:AI 复盘工具(CLI/Web)在模型成型后再设计,YAGNI。

### 明确不做(YAGNI)

- 不碰雀魂真人局(封号风险)
- 复盘工具 UI 后置
- 阶段 2 前不做天凤接入
- 不重写网络结构(先用上游 ResNet 架构)

## 3. 总体架构

```
│  │  数据层    │───▶│  引擎层    │───▶│  训练层    │   │
│  │ tenhou-   │    │ libriichi │    │ GRP →     │   │
│  │ to-mjai   │    │ (Rust,    │    │ DQN(CQL)  │   │
│  │ 250万局   │    │  PyO3)    │    │ → 可选自对弈│   │
│  └───────────┘    └───────────┘    └───────────┘   │
│        │                                │           │
│        ▼                                ▼           │
│  ┌─────────────────────────────────────────────┐    │
│  │             评估层 (mjai 协议)               │    │
│  │  duplicate mahjong · vs akochan/Mortal      │    │
│  └─────────────────────────────────────────────┘    │

```

### 组件划分

| 组件 | 职责 | 依赖 | 独立测试 |
|---|---|---|---|
| 数据层 | 下载/校验 MJAI 数据,构建训练数据集索引 | 无(纯脚本) | ✅ |
| 引擎层 | fork 的 libriichi:Rust 模拟器 + 特征提取 + PyO3 绑定 | Rust 工具链 | ✅(自带测试) |
| 训练层 | GRP 训练 → DQN 离线训练 → 可选在线自对弈 | 引擎层 + PyTorch | ✅ |
| 评估层 | mjai 协议对战、duplicate mahjong 强度测试 | 训练层产物 | ✅ |

### 关键架构决策

1. **fork 而非依赖引用**:完整 fork Mortal 主线仓库,保持 upstream 同步能力。AGPL 接受(自用无碍)。
2. **配置差异管理**:自定义配置(数据路径、批次、超参)通过配置文件/环境变量注入,不硬改上游代码。
3. **双机形态**:开发在 `/root` 控制台,训练在 5070Ti;同一 git 仓库同步。训练机跑"数据层+训练层",控制台跑"评估层"。

## 4. 数据流与训练管线

```
[1] tenhou-to-mjai 数据集 (12GB, 250万局, .mjson.gz)
        │ 下载 + 校验 + 本地归档 + 目录索引
        ▼
[2] 训练样本库 (libriichi GameplayLoader 提取)
    obs (1012×34) · actions · masks · kyoku · dones
        ├──▶ [3a] GRP 训练 (train_grp.py, 顺位预测模型)
        │         输出: GRP 权重 (小模型, 小时级)
        └──▶ [3b] DQN 离线训练 (train.py, CQL + GRP奖励)
                 输出: 第一版主模型 (b40c192 ≈ 11M 参数)
                        │ 5070Ti 上数天
                        ▼
        [4] 评估闭环 (duplicate mahjong, mjai 协议)
            对战 akochan / 与 Mortal 官方基准对比
                        │
                        ▼
        [5] (可选,阶段2) 在线自对弈微调 (server+client+train)
            用 libriichi 模拟器 4万半庄/时 跑自对弈数据
```

### 训练策略

- **先 GRP 后 DQN**:GRP 是奖励模型,是 DQN 的依赖,必须先训练(小模型、训练快)。
- **离线 DQN 用 CQL**:`min_q_weight=5`,离线数据上稳定;一次 epoch 跑完 250 万局为数天量级——**主训练循环**,调参迭代重复此过程。
- **评估优先于调参**:每次训练出模型先跑 duplicate mahjong 基准(对 akochan,1v3 各约 2000 局),有数字才迭代。
- **阶段 2 再考虑在线自对弈**:online RL 对超参敏感,先把离线基线做扎实。

### 错误处理与鲁棒性

- 下载支持断点续传 + 校验和;数据损坏局自动跳过并记录。
- 训练中断可恢复(检查点 + state_file 续训)。
- 评估结果结构化存档(JSON),支持历史强度对比曲线。

## 5. 阶段划分与里程碑

| 阶段 | 内容 | 验收标准 | 预计耗时(5070Ti) |
|---|---|---|---|
| **P0 环境就绪** | 安装脚本:Ubuntu 依赖、Rust、Python 3.12、CUDA、PyTorch;fork Mortal;构建 libriichi | `libriichi` 构建通过,`import mortal` 成功 | 1-3 天 |
| **P1 数据就绪** | **尽早下载 12GB 数据集** + 校验 + 本地归档 + 索引;数据管线冒烟测试 | 数据完整性校验通过;GameplayLoader 处理全部 250 万局,产出首批样本 | 2-4 天 |
| **P2 GRP 训练** | train_grp.py 训练顺位预测模型 | GRP 验证集顺位预测准确率达标 | 0.5-1 天 |
| **P3 离线 DQN** | train.py 离线 CQL 训练主模型(数天/轮),检查点续训 | 第一版模型能跑评估;**基准:打赢 akochan**(duplicate mahjong 顺位分转正) | 1-2 周(每轮数天) |
| **P4 迭代打磨** | 调参、数据筛选(高段位/异常局排除)、多轮训练 | 强度曲线稳定上行,逼近 Mortal 官方基准 | 3-6 周 |
| **P5 自对弈微调**(可选) | 在线 RL 自对弈,libriichi 模拟器 | 相比 P4 模型有统计显著提升 | 2-4 周 |
