## 0. Verdict in one page

1. **No existing corpus is trainable.** Tenhou raw logs, the `tenhou-to-mjai` derived
   archives (including the local `datasets/` copy), Mortal code/weights, akochan, Majsoul,
   and third-party mirrors are all `UNKNOWN` or `RESTRICTED` for training. The gate rejects
   every production source for `--purpose train`.
2. **Publicly downloadable is not a licence.** The Tenhou manual says game records are
   published to support fair play on Tenhou, that application to services not requiring
   Tenhou play is not permitted (free or paid), and that general mahjong application
   requires contacting `support@c-egg.com` first. The raw-log page separately prohibits
   redistribution of record files and the record index.
3. **A converter's code licence is not a data licence.** `tenhou-to-mjai` code is
   Apache-2.0, but its `LICENSE-DATA` says it claims no ownership, grants no CC BY or other
   licence over the logs, and has no explicit redistribution permission from Tenhou/C-EGG.
   Its `NOTICE` nonetheless claims CC BY 4.0 for the dataset — a direct contradiction.
   This review takes the most restrictive reading and does not rely on the CC BY claim.
4. **Mortal's AGPL code does not license Mortal weights.** The upstream author stated in
   2022 that there was no plan to release trained weights; the pinned repository has 0
   releases and 0 tags. Local teacher checkpoints have no recorded weight licence. Code
   rights, weight rights, and Tenhou data rights are three separate questions.
5. **akochan is eval-only.** Its custom Japanese terms permit non-public research use, but
   non-commercial output republication requires attribution, other uses require the
   author's permission, and redistribution with AI-part modifications is prohibited in
   principle. It is not an OSI licence.
6. **The legal alternatives are self-play/own rule bot and explicitly licensed data.**
   Self-play is the recommended path, but **no self-play corpus exists yet**. Its row stays
   `UNKNOWN` until the corpus is generated by our own rule engine, passes H-04 rule parity
   and the G2 legality gate, and receives human rights/provenance sign-off. Synthetic
   fixtures may be used for code tests now.
7. **Do not start training, distillation, or new corpus downloads** until a human flips a
   source to `ALLOWED` with exact-scope evidence and the gate passes. Existing local data
   remains read-only audit material; this review does not authorize continued use for
   model development.

### 1.2 Evidence levels (from `00_REVIEW_FINDINGS.md` §4)

| Level | Meaning | Used here for |
|---|---|---|
| **A** | Directly fetched source text or locally inspected file | Tenhou manual clauses, `/sc/raw/` clauses, converter `LICENSE-DATA`/`NOTICE`, Mortal/local AGPL text, akochan licence, gate behaviour |

This document does not upgrade B or C claims to A. Where a page could not be fetched, the
row is `UNVERIFIED` and the exact error is recorded; no clause was invented.

### 1.3 Fail-closed decision rule

For each source and each purpose:

| Observed evidence | Registry value |
|---|---|
| Exact-scope permission, with URL + verbatim quote + retrieval date + human reviewer | `ALLOWED` |
| No evidence for that exact scope, or evidence is ambiguous/contradictory | `UNKNOWN` |
| Operator terms state a restriction, permission requirement, or prohibition for that scope | `RESTRICTED` |

`ALLOWED` is not inferred from: public download availability, a code licence, a third-party
redistribution, a mirror's metadata, the fact that data is already on disk, or the fact that
other projects trained on it. The gate requires all evidence fields plus a reviewer that is
not marked as an AI/draft/pending review.

## 4. Per-source analysis

The subsections below separate **storage**, **training**, **redistribution**, and
**privacy/player identifiability**. `status` is the row-level verdict (any `ALLOWED`
purpose makes the row `ALLOWED`; otherwise restrictions win over `UNKNOWN`).

### 4.1 `tenhou_raw_logs` — official raw Tenhou records

**What it is**: XML game records downloaded from Tenhou's official archive / in-game log
feature, before any MJAI conversion. Not the same artifact as the `tenhou-to-mjai` release,
although both ultimately contain the same games.

**Evidence (A)**: `man/` (paifu-use section) and `/sc/raw/` quotes in §3; `※牌譜の著作権は天鳳にあるものとします`.
Retrieved 2026-11-21.

| Purpose | Value | Reasoning |
|---|---|---|
| Storage | `UNKNOWN` | The archive supports downloading for viewing/fair-play support, but no clause grants retention for model development. Fail-closed: no exact-scope storage licence. |
| Training | `RESTRICTED` | The paifu-use section says unrelated-service application is not permitted and general mahjong application requires contacting the operator first. No permission obtained. |
| Redistribution | `RESTRICTED` | `/sc/raw/` explicitly prohibits redistribution of record files and the index; copyright is asserted by Tenhou. |

different licensed source. A public-download link alone does not change it.

## 5. Privacy and player identifiability

This is a separate axis from copyright. Even if a copyright licence were obtained, personal
data processing would still need a lawful basis and minimisation.

### 5.1 What the official terms establish

- `性別情報は牌譜に記録されます。` — gender is recorded in the records.
- Player names can be displayed; `&tw=?` removes them at **view time**, not from the stored
  file. The manual says removing the parameter anonymises the display, which implies the
  underlying record retains the linkage.
- The operator asserts copyright and may delete or reformat records without notice.

### 5.2 Risks in the current pipeline

- MJAI conversion may carry `start_game.names` (the project's own synthetic fixtures use a
  `names` field). If real logs are converted, names can survive.
- Raw Tenhou log URLs and 16-hex suffixes are stable identifiers; even without names, they
  can be joined to public rankings or other mirrors.
- Gender flags and seat histories can enable inference about small player populations,
  especially in the Phoenix room.
- The existing `provenance.py` says player identity is not part of the schema, but that is a
  design statement, not an enforced sanitizer. A shard builder could still copy a `names`
  field unless it explicitly drops it. **P2-1** records this gap.

### 5.3 Required controls before any future shard

1. Drop `names`, account IDs, gender flags, raw log URLs, and any free-text fields from the
   training record.
2. Replace player identity with randomised seat indices per game; never join across games
   or sources.
3. Do not build per-player skill/rank profiles or re-identification demos.
4. Keep raw archives access-controlled; do not publish samples or derived shards.
5. Define retention and deletion; a permission that can be withdrawn must have a kill path.
6. Treat any human evaluation games as a separate consent/retention question.
7. If a privacy-law analysis is needed (APPI/GDPR/etc.), obtain it from a qualified person;
   this review does not provide one.

## 6. The fail-closed gate

### 6.1 What it does

`scripts/rf_check_source_rights.py` reads the CSV and answers one question:

```bash
python scripts/rf_check_source_rights.py \
    --source tenhou_old --purpose train \
    --csv configs/riichiformer/source_rights.csv
```

- Exit `0`: the row-level `status` is `ALLOWED` **and** the purpose cell is exactly
  `ALLOWED`, with a concrete evidence URL, a verbatim quote of at least 20 characters, a
  non-future ISO retrieval date, non-empty privacy notes, and a reviewer that is not marked
  AI/automation/draft/pending.
- Exit `1`: the source is known but the requested purpose is not `ALLOWED`.
- Exit `2`: malformed registry, unknown source, missing file, or invalid CLI usage.

Actual output today:

```text
$ python scripts/rf_check_source_rights.py --source tenhou_old --purpose train
DENY source=tenhou_old purpose=train status=RESTRICTED reason=status=RESTRICTED (need ALLOWED; train_allowed=RESTRICTED)
$ echo $?
1

$ python scripts/rf_check_source_rights.py --source not_a_source --purpose train
ERROR source=not_a_source purpose=train reason=unknown source 'not_a_source'; not configured = fail closed
$ echo $?
2
```

### 6.2 Validation rules

The gate rejects a registry if any of the following holds:

- missing required column, duplicate header, padded/blank header, duplicate `source_id`;
- a registry containing some but not all of the 11 known source ids (a truncated production
  registry is rejected globally; a fixture-only registry remains valid for gate tests);
- a row with too many cells, an empty provenance field, a non-ISO `retrieved_at`, or a
  `retrieved_at` later than **today UTC** on an `ALLOWED` row;
- a purpose/status value outside `{ALLOWED, UNKNOWN, RESTRICTED}`;
- a `status` that is inconsistent with the purpose cells: any `ALLOWED` purpose requires
  `status=ALLOWED`; with no allowed purpose, any `RESTRICTED` requires
  `status=RESTRICTED`, otherwise `status=UNKNOWN`. A row cannot set `status=ALLOWED` when
  every purpose is blocked;
- an `ALLOWED` cell with a non-http(s) `evidence_url`, an `UNKNOWN`/empty `terms_url`, a
  short/empty quote, a missing/future date, empty privacy notes, or a reviewer containing
  `pending`, `tbd`, `unreviewed`, `ai agent`, `draft`, or `n/a`;
- an `ALLOWED` reviewer containing an AI/automation token (`AI`, `LLM`, `GPT`, `ChatGPT`,
  `bot`, `automated`, plus compact forms `chatbot`/`openai`), matched case-insensitively as
  a token so a human name such as `Kaito` is not rejected for containing `ai`.

The reviewer check is intentional: **this agent can collect evidence but cannot approve a
source.** A row whose reviewer is "H-03 Dev-C (AI agent; evidence draft; no human
sign-off)" can never become `ALLOWED`, even if someone accidentally flips a purpose cell.

The **requested purpose cell is authoritative once the row-level status is `ALLOWED`**.
If any purpose is `ALLOWED`, `status` must be `ALLOWED`; a purpose can never pass while
`status` is `UNKNOWN`/`RESTRICTED`. A source may allow local storage while restricting
training and redistribution; the gate will allow the former and deny the latter, and the
registry notes must say why. `check()` re-runs the row/status/evidence validation even for
a hand-built dict that bypassed `load_registry()`.

### 6.3 What it does **not** do

- It does not fetch URLs or verify that a quote appears at the URL. Evidence verification is
  a human review step; the gate checks presence and shape, not truth.
- It does not interpret the terms, decide fair use, or decide whether a use is "general
  mahjong application" or a "competing product".
- It does not sanitize names or enforce privacy controls. That is a separate shard-builder
  gate (P2-1).
- It does not distinguish "pre-existing local read-only audit" from "new copy/shard".
  `--purpose storage` denies **new** storage; the existing local archives are outside this
  gate and remain read-only audit material. Do not use them to build training shards.
- It does not integrate itself into `rf_build_shards`/training. **P1-3** records the wiring
  gap. Until the data lane calls the gate, the operational rule "do not train" still
  applies.

### 6.4 Registry schema

| Column | Meaning |
|---|---|
| `source_id` | Stable id; unique; no whitespace. Existing provenance ids (`tenhou_old`, `tenhou_recent`, `teacher_local`, `selfplay_own`, `majsoul_optional`) are preserved. |
| `origin_url` | Where the source comes from (archive/repo page). |
| `retrieved_at` | Date this review fetched/read the evidence (`YYYY-MM-DD`). |
| `terms_url` | Operative terms/licence page (not a 404). |
| `evidence_url` | Specific page/file for the quoted evidence. |
| `evidence_quote` | Short verbatim clause supporting the row's scopes. |
| `storage_allowed` | Per-purpose verdict. |
| `train_allowed` | Per-purpose verdict. |
| `redistribute_allowed` | Per-purpose verdict. |
| `privacy_notes` | PII/identifiability handling requirements. |
| `status` | Row-level verdict: `ALLOWED` iff at least one purpose is `ALLOWED`; otherwise `RESTRICTED` if any purpose is `RESTRICTED`, else `UNKNOWN`. |
| `reviewer` | Who reviewed; AI/draft/pending markers block `ALLOWED`. |
| `notes` | Reasoning, contradictions, next steps. |

### 6.5 How to flip a row to `ALLOWED`

1. Obtain exact-scope written permission or a licence that covers the purpose. Save the
   document/text and a stable URL.
2. Have a human with authority read it and record their name in `reviewer`.
3. Put a short verbatim quote and the retrieval date in the row.
4. Set only the purpose cells the evidence covers. Set `status=ALLOWED` if any purpose is `ALLOWED`; otherwise set `RESTRICTED` if any purpose is restricted, else `UNKNOWN`.
5. Run `pytest tests/rf_test_source_rights.py` and the gate for each purpose.
6. Do not flip a data row on the basis of a code licence, a mirror, or "it is public".
   Do not let an AI agent be the reviewer.

### 6.6 Follow-up hardening (review fixes)

The first H-03 commit was reviewed and the gate was hardened without weakening fail-closed
behaviour:

- Reviewer markers now reject plain `AI`, `LLM`, `GPT`, `ChatGPT`, `bot`, and `automated`
  case-insensitively, as tokens (plus `chatbot`/`openai`), so a human name containing
  `ai` such as `Kaito` is not falsely rejected.
- `retrieved_at` later than today **UTC** is rejected on `ALLOWED` rows.
- `check()` revalidates the row and status, so a hand-built row with
  `status=UNKNOWN`/`train_allowed=ALLOWED` is rejected even if it bypassed
  `load_registry()`.
- The tests assert exactly 11 production rows and the exact 11 `source_id`s; a known
  default missing from the registry is a hard error (`missing from the registry`), and a
  partial production registry is rejected globally rather than silently accepted for its
  remaining rows.
- New tests cover all four items; the follow-up log records the new counts. All 11
  production rows remain non-`ALLOWED`.

## 7. Findings

### P0-1 — No training source is allowed

All 11 rows are non-`ALLOWED` for training. This is the intended fail-closed state after
H-03: the evidence does not support training on Tenhou raw/derived records, Mortal weights,
akochan outputs, Majsoul, or an unverified mirror. **PR-12/14 must not start real training**
until a human flips a source and the gate passes.

### P1-1 — Converter `NOTICE` contradicts `LICENSE-DATA` on CC BY 4.0

`NOTICE` claims CC BY 4.0 for the dataset; `LICENSE-DATA` says no CC BY or other licence
over the logs, and Tenhou prohibits redistribution. A downstream user could mistakenly
rely on the CC BY claim. This review takes the restrictive reading and records it. The
converter should be asked to resolve the contradiction in writing; until then, no
redistribution/training.

### P1-2 — `provenance.py` cites a 404 terms URL; `#PAIFU` is not an anchor

`provenance.py` uses `https://tenhou.net/term.html`, which returns HTTP 404. The operative
clauses are on `man/` and `sc/raw/`. The current manual also has no `#PAIFU` anchor; the
paifu-use heading sits between `#AI` and `#ETC`. Do not cite `term.html` or `#PAIFU` as
evidence. The file was not edited because it belongs to another lane; the Lead should fix
the citation and consider reading the new CSV instead of the hard-coded defaults.

### P1-3 — The new registry is not wired into the shard/training path

`riichiformer/data/scan.py` still writes the old-schema `artifacts/.../source_rights.csv`
(columns `rights_status`, `display_name`, ...), and `provenance.default_source_rights()` is
hard-coded. The new gate/CSV is a standalone control. Before PR-12/14, the data lane must
either call the gate or replace the old registry reader. The gate rejects the legacy CSV as
malformed (tested), so passing the old artifact cannot silently open training.

### P1-4 — Mortal weights have no recorded licence or provenance

The author says there is no plan to release trained weights; the repo has 0 releases/tags;
local checkpoints have no provenance record. Distillation/teacher-label use is therefore
`UNKNOWN` for training and `RESTRICTED` for redistribution. Do not use the AGPL code licence
as a weight licence.

### P1-5 — The documented download URL is 404

`scripts/download_data.py` targets `.../releases/download/v2.0.0/{year}.zip`. On
2026-11-21 both the tag page and the `2009.zip` asset returned **HTTP 404**; the
releases index is 200 and the README now points at HuggingFace/torrent. The local
`datasets/` files therefore have no currently working official download path from the
recorded URL. Re-verify a mirror, hash the local files, and update the downloader only
after rights review. This does not change any rights verdict; it is a provenance and
reproducibility blocker.

### P2-1 — No enforced PII sanitizer

Names/gender/URLs may survive conversion. The schema statement in `provenance.py` is not an
enforcement mechanism. Add a sanitizer/validator before any shard, with tests that a
`names` field cannot reach a training record.

### P2-2 — Mirror and local-copy provenance gaps

The HuggingFace mirror could not be fetched; local `datasets/` copies have no per-file
provenance beyond the download script and the audit report. Do not treat "already on disk"
as authorization or as proof of integrity.

### P2-3 — 2026 is January-only

2026 contains 12,188 files (January only) per `DATA_REPORT.md` (B). It is not a complete
year and should not be described as a fresh confirm set.

## 8. What cannot be concluded

This review **cannot** conclude any of the following; a qualified human/legal reviewer must:

- whether any particular use is lawful or unlawful, including fair use/quotation, in any
  jurisdiction;
- whether training a model is a "service that does not require playing on Tenhou", a
  "general mahjong application", or a "competing product" under Tenhou's terms;
- whether Tenhou would grant permission if asked, or on what conditions;
- whether model weights are a derivative work of the training records, or whether training
  on records produces a licensable model;
- whether the converter's `NOTICE` CC BY 4.0 claim has any legal effect despite
  `LICENSE-DATA` and upstream restrictions;
- whether local `datasets/` files are unmodified copies of the official archive;
- whether the local teacher checkpoint came from an authorized source;
- whether the HuggingFace mirror's terms are compatible (page **UNVERIFIED**);
- whether processing names/gender is compliant with APPI, GDPR, or any other privacy law;
- whether player consent exists for any record in the corpus.

The registry records evidence and missing evidence; it does not answer these questions.

## 9. What a human would need to unblock training

### 9.1 Tenhou / derived corpus

A written permission from C-EGG (`support@c-egg.com`) that explicitly covers:

- storage/retention of the records (and for how long);
- training of models, including whether model weights and outputs are covered;
- internal evaluation and any external publication;
- redistribution of records, derived data, and model weights (or an explicit statement
  that redistribution is not permitted, so the project can design around it);
- commercial vs non-commercial scope, and any sponsorship/attribution requirement;
- derivative works and converter output;
- privacy/player-data handling (names, gender, identifiers), deletion/withdrawal;
- whether the resulting AI may play on Tenhou, and under which ID/table rules
  (`#AI` currently says no new AI-only IDs and no Phoenix play).

Then: a human reviewer records the exact scope in the CSV, sets only the covered purpose
cells to `ALLOWED`, updates `status`, and reruns the gate/tests. A generic "research is fine"
email is not enough if it does not cover the exact purpose.

Alternative: an explicitly licensed corpus whose licence covers model training and the
intended redistribution. Check the licence text, not a dataset card summary; CC BY may
require attribution and may not cover third-party rights in the records.

### 9.2 Self-play / own rule bot

- A generator we own, with a documented commit and ruleset id.
- No Tenhou/Majsoul ranked play and no platform-derived seeds/logs.
- H-04 rule parity and G2 legality tests passing.
- Synthetic seats; no human names/gender.
- A human rights/provenance review that flips `selfplay_own.train_allowed` to `ALLOWED`.
- A retention/redistribution plan; if the engine is AGPL Mortal-derived, review derivative
  and source-offer obligations first.

This is the recommended route because it does not depend on a third-party data grant.

### 9.3 Mortal weights

- A written weight licence from the author, or a documented public release under a named
  licence, plus provenance for the exact local file; or
- retrain the teacher from scratch on a licensed corpus; and
- a separate legal view on whether weights derived from Tenhou records carry upstream
  restrictions.

### 9.4 akochan

- Author permission for training/output use and for any modified redistribution; or
- use it only as an unmodified eval opponent under the non-commercial/attribution terms,
  with no training on its outputs.

### 9.5 Majsoul

- Written platform permission plus a privacy review; currently out of scope.

## 10. Recommended path (do not weaken the gate)

1. **Stop**: no new Tenhou downloads, no shard build for training, no distillation, no
   training run on the existing corpus.
2. **Build the legal alternative**: own rule engine → self-play with synthetic seats →
   H-04 parity + G2 legality → human sign-off → `selfplay_own` training row.
3. **Use synthetic fixtures** for PR-13/14 code tests in the meantime; they exercise the
   model/trainer without consuming restricted data.
4. **Ask C-EGG in parallel** with the exact scope in §9.1; if granted, update the registry
   and rerun the gate. Do not train "first and paper over later".
5. **If a licensed corpus appears**, add a new row with exact evidence and a human reviewer;
   never relabel an existing restricted row on the basis of a summary or a mirror.
6. **Keep the gate in CI** and keep `UNKNOWN`/`RESTRICTED` blocking. The gate is an
   operational safety rule, not a legal opinion.
