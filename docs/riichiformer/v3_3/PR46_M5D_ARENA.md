## 2. Relative PT scorer (`riichiformer/eval/relative_pt.py`)

```text
TOKUJOU_5D_HANCHAN = [75, 30, 0, -105]    # primary
HOUOU_7D_HANCHAN   = [90, 45, 0, -135]    # auxiliary / historical eval_report
pt5_C = profile[rank_C-1]
pt5_M = mean(profile[rank_M-1] for the three Mortal seats)
delta_pt5 = pt5_C - pt5_M = 4/3 * pt5_C
```

* ranks: score descending, ties by lower absolute seat (native `rankings.rs` rule);
* one complete set = one wall seed × four absolute seat rotations; set metrics are
  averages over its four games; per-set `pt5_C`, `delta_pt5`, `avg_rank`, `rank_hist`
  are reported alongside the raw values;
* block bootstrap resamples **complete sets** only, B=2000, fixed seed
  `0x52463641` (`RF6A`), percentile 95%;
* fail closed on: incomplete set, missing/extra/duplicate wall seed, duplicate
  rotation/game id, score sum ≠ 100000, supplied ranks that disagree with scores,
  mixed/wrong seed key, incomplete game;
* no old 500-set / 3000-set gate is present or referenced.

## 3. Native arena (`riichiformer/eval/m5d_arena.py`, `scripts/rf_eval_m5d.py`)

Champion: three identical `M5D-R0` seats. Candidate modes:

* `--candidate mortal` — anchor **self-control only**. The same checkpoint plays
  the candidate seat. This is a rotation/seed/arena bias check; the report sets
  `self_control_only=true` and `rf_candidate=NOT_RUN`.
* `--candidate rf --checkpoint PATH` — an RF checkpoint policy in an
  `engine_type='mjai-log'` seat. For every native reaction:
  1. the current visible log (`game_state.events_json`) is accumulated over the
     game and re-projected with `POVProjector` (opponent hands/ura/ankan masked);
  2. `_SnapshotTracker` rebuilds the POV-safe `DecisionInput` (native 46-mask,
     phase, public state);
  3. `encode_decision` + `Policy.forward` produce masked logits; argmax is the
     action;
  4. the action context is built from the **native `PlayerState`**
     (`tehai`/`akas_in_hand`, `last_self_tsumo`, `last_kawa_tile`,
     `cans.target_actor`, native kan candidates), then decoded with
     `riichiformer.runtime.mjai_adapter`;
  5. the concrete event is passed to `state.validate_reaction` before returning.

  The native-state context prevents the false `tsumogiri` found during
  integration; kakan events get the well-formed three-tile `consumed` list the
  native deserializer requires; a multi-kan decision uses the first native
  candidate deterministically. There is no random/fallback action: any illegal or
  rejected reaction aborts the run.

Scores are settled from the four dumped native logs with
`replay_scores(strict_protocol=False)` and cross-checked against the native
rankings array. `run.json`, `report.json` and `games.jsonl` carry per-game
scores/ranks, per-set summaries and file SHA-256s. `guard_output_dir` refuses
`runs/1v3`, `runs/variance`, `checkpoints`, `datasets`, `vendor` and the repository
root. The CLI generates a fresh 64-bit wall key with `secrets.randbits(64)` and
records it plus the wall window.

## 5. P0 / P1 / P2

* **P0:** none observed. No hidden-tile input (projection + `DecisionInput`
  forward-safety), no illegal/fallback action, no score-sum/rank mismatch, no
  frozen-path write, no weight mutation.
* **P1:** the RF bridge sees the **visible per-kyoku log accumulated into the full
  game history**, which matches the training stream shape; it cannot see prior
  hidden events or the wall order. If a future model is trained on a different
  context scope, record it in the manifest (`context_scope`).
* **P1:** the native `mjai-log` agent does not deliver the settlement tail of a
  completed kyoku (the final `hora`/`ryukyoku`/`end_kyoku` events after the last
  reaction); the next `start_kyoku` carries the authoritative scores and the
  tracker resets there. The RF prefix therefore has a boundary gap, not a hidden
  tile. Record this if a future candidate is compared across context scopes.
* **P1:** `RFPolicyBackend.from_checkpoint` loads the PR-14 checkpoint with
  `torch.load(weights_only=False)` because the payload carries RNG state objects
  (numpy) that `weights_only=True` refuses. The file SHA-256 is recorded; only
  trusted local research checkpoints are accepted. The Mortal anchor uses
  `weights_only=True`.
* **P2:** the anchor registry records `python_driver_files` hashes; regenerating
  the registry is required after driver edits (the canonical hash changes).
* **P2:** `PovDecisionStream` reuses `data.decision._SnapshotTracker` (private); if
  that helper moves, the bridge needs an update. Its full-history rebuild is
  O(game events) once per kyoku, not once per decision.
* **P2:** R29 (consecutive kakan/chankan ippatsu timing) is `MATCH` at the PlayerState level (PR-40R), while a full Board-scripted game remains `NOT_RUN`; the shard-level metadata still lists it as a known deviation because the frozen per-decision enum has no R29 member (PR-40)
