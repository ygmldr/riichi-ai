## 1. What was implemented

1. **`riichiformer/data/canonicalize.py`** — lossless MJAI canonical form:
   - magic-based gzip/plain decode, strict one-JSON-object-per-line parsing (line number in errors);
   - event order/fields preserved; unknown event types and fields kept (no schema migration, no repair,
     no hidden-tile or future-result recomputation);
   - stable serialisation: sorted keys, compact separators, UTF-8; `original_sha256` over raw bytes and
     `canonical_sha256` over the canonical text;
   - Tenhou log id extracted from the filename → `game_id = tenhou:<id>`, else `sha256:<canonical>`;
   - rejects missing/duplicate `start_game`/`end_game`, nested/unpaired/absent `start_kyoku`/`end_kyoku`,
     empty logs, bad UTF-8/JSON, unknown compression. Invalid rows keep the reason; nothing is "fixed".
2. **`riichiformer/data/dedup.py`** — priority dedup:
   - group by `platform_game_key` first, then `canonical_sha256`;
   - same id + different canonical hash → `collision_review=true` (never merged silently);
   - same canonical content under different ids → `cross_key_duplicate=true` for review;
   - deterministic representative (smallest original SHA, then relpath), so one copy per game is retained;
   - Parquet schema `rf-log-index/1`, stratified deterministic sampler (`seed=20261121`).
3. **`scripts/rf_build_canonical.py`** — builds the index from the PR-02 Parquet inventory; `--sample`
   (default 1000) or `--all`; writes `canonical_log_index.parquet`, `sample_*.jsonl`, `summary.json`,
   and explicitly records `full_corpus`.
4. **`tests/rf_test_canonicalize.py`** — 16 tests: gzip vs plain hash equality, public-event hash
   sensitivity, platform/game_id, missing/unpaired kyoku, bad JSON line, empty/unknown compression,
   invalid-row preservation, canonicalize_file, same-content duplicate group, platform priority,
   same-id collision, cross-key review, invalid rows not grouped, Parquet roundtrip/schema,
   deterministic stratification, CLI end-to-end.

## 5. Risks / limitations

- **Full corpus is NOT canonicalised.** `full_corpus=false`; the sample index must **never** be used as
  the PR-05 split registry. Measured rate: 1,000 games / 20.76 s ⇒ ~14.4 h single-thread for 2,512,424 games
  (4 workers ≈ 3.6 h; 12 workers ≈ 1.2 h, excluding I/O). This is compute, not a licence blocker, and must
  be scheduled explicitly rather than silently skipped.
- The sample has no duplicates, so real-corpus duplicate prevalence is UNKNOWN; dedup behaviour is proven
  by synthetic fixtures, not by the 1,000-game sample.
- Canonicalisation preserves unknown fields by design; it therefore also preserves any hidden/future data
  present in the raw log. POV projection is PR-09 and must never be assumed from this layer.
- Strings/numbers are re-serialised (whitespace/key order only); if an upstream writer emits `1.0` vs `1`
  the JSON parser preserves the value but not the original byte spelling — `original_sha256` still catches
  byte-level differences, `canonical_sha256` intentionally treats them as the same event value.
