## 1. What was implemented

1. **`scripts/rf_preflight.py`** — read-only preflight (single JSON artefact):
   - git HEAD / branch / remote / tracked+untracked dirt (porcelain parsed without corrupting the
     status column), submodule index & HEAD SHA, dirty entries, `[patch NNNN]` marker census;
   - SHA-256 + bytes + mtime for required baseline files, all 12 patches, all checkpoints and the
     built `libriichi.so`; aggregate `baseline_files_hash`;
   - Python / PyTorch / CUDA / GPU / BF16 probe in a **subprocess** (auto-prefers `.venv/bin/python`,
     so a bare system Python still yields honest torch facts);
   - `nvidia-smi` probe including the WSL path (`/usr/lib/wsl/lib/nvidia-smi`), Rust toolchain probe
     (PATH **and** `~/.cargo/bin`), `import libriichi` probe with `ACTION_SPACE`;
   - CPU `torch.load` of every checkpoint with `weights_only=False`, reporting keys, state-dict name
     (`mortal`/`current_dqn`/`aux_net` layout), tensor/param counts, `steps`, `timestamp`,
     `config.model.use_event_branch`, and whether event weights actually exist;
   - `status ∈ {PASS, WARN, BLOCKED}`, `gate.G0`, blockers, warnings, per-check results;
   - **never** downloads, installs, trains, touches the network, or creates a missing weight.
     Exit codes: `0` = no blocker (warnings allowed), `2` = BLOCKED, `3` = internal error;
     `--strict` turns WARN into `1`.
2. **`tests/rf_test_preflight.py`** — 21 tests (stdlib `unittest`, also collectable by pytest):
   required schema keys, real git SHA, tracked-vs-untracked dirt, missing required file ⇒ BLOCKED and
   **file not recreated**, missing checkpoint ⇒ `NOT_FOUND`/WARN and **directory not created**,
   only-output-file-written (full tree hash comparison), submodule missing ⇒ BLOCKED, patch gap
   handling (`0011` documented), submodule dirty warning, `--strict`, stdout-JSON/stderr-summary
   separation, deterministic core, baseline hash sensitivity, real runtime probe shape, checkpoint
   readable + config flag, corrupt checkpoint ⇒ WARN without crash, porcelain first-line regression,
   sha/status helpers, interpreter preference.
3. **`docs/riichiformer/BASELINE_LOCK.md`** — frozen evidence for git/submodule/patches/config/
   checkpoints/eval protocol + risk register R-01…R-12.
4. **`docs/riichiformer/EVAL_POOL_REGISTRY.md`** — every seed_key and wall-seed window with disk and
   document evidence; marks consumed windows (incl. the previously under-documented M3
   `[120000,126000)`), frozen corpora, and the process gap around pool B.
5. **`.gitignore`** — added `artifacts/riichiformer/`, private player-map/HMAC/salt patterns,
   `*.key`, `.env*`, `docs/riichiformer/private/` (datasets/checkpoints were already ignored).
6. **`docs/riichiformer/handoff/`** — verbatim copy of the v1.0 spec pack (6 md + 4 config templates),
   so task cards and acceptance criteria are versioned with the code. Aggregate SHA-256 over
   `sha256("relpath:sha256\n")` of all 10 files:
   `3b969ca19eb68ffb0dbf535f3da7e3b70846e470760509d9436780ba182ef0aa` (e.g.
   `00_MASTER_PLAN.md` = `7414227c…e13d`, `01_TASK_CARDS.md` = `f7e6b115…a2e`).

No training, no evaluation, no data download, no seed consumption, no `vendor/mortal` edit.
`runs/**` was only read.

## 7. Known risks (full register: `BASELINE_LOCK.md` §7)

- **R-01 (P0, future training)**: patch 0006 event tokenizer leaks opponent `tsumo` and omits own
  haipai. Not fixed here (PR-09). Live checkpoint is plain CNN (`use_event_branch=false`), so do not
  mislabel the deployed Mortal baseline as violating.
- **R-02 (P1)**: 3 submodule source files are untracked and absent from `patches/`; their hashes are
  frozen, but a patch-only replay cannot reproduce the tree. Fix in a later vendor/patch PR.
- **R-03 (P1)**: `git submodule update --force`/checkout would destroy the applied patch state.
- **R-05/R-06 (P1)**: A14 confirm `[70000,73000)` and M3 `[120000,126000)` are **consumed**; the live
  config's `use_event_branch=true` would rebuild the leaky branch if training started. Training stays
  blocked until G2.
- **R-10 (P2)**: GPU had ~4.9 GB used at preflight time; single-slot assumption must be verified in
  PR-01.
- **R-11 (P1)**: `configs/config.toml` is a **live-path config** (points at `checkpoints/mortal.pth`,
  `checkpoints/best.pth`, `runs/`, `runs/test_play`, `runs/train_play`, and the frozen corpus
  `runs/variance/pool_3/games/`). Experiments must deep-copy + redirect + read back; never point a
  new arm at it.
- **R-12 (P2)**: `best_perf={avg_rank:1.0, avg_pt:90.0}` is a sentinel on `best/at-175200/mortal`,
  not a measurement. Do not cite it as baseline performance.
- **Patch-marker caveat**: only 5 of 12 patch files contain `[patch NNNN]` markers (7 contain none),
  so the 29-marker census proves the *tree* is patched, not that every patch was replayed. Exact
  applied state is pinned by the dirty diff hash + all per-file hashes in BASELINE_LOCK §1.
