## 1. What was implemented

1. **`riichiformer/data/split.py`**
   - `Protocol L`: train 2009–2022, `val_holdout` 2023, 2024–2026 → `external_diagnostic`
     (explicitly not pristine confirmation);
   - `Protocol R`: train 2009–2024, val 2025 H1, model-select 2025 H2, 2026 →
     `confirm_blocked_previously_used` (local 2026 is January only and was used by EX1);
   - month parsed from the Tenhou filename prefix (`YYYYMMDDHH…`), missing month → `undated`
     (fail closed; never guessed); non-Tenhou filename → `unknown_id`;
   - `hash_fallback` deterministic mode implemented and marked `not_temporal` (not used here);
   - one row per `game_id`, so four POVs and all labels of a game share one split;
   - `blocked_source` / `rights_status` / `train_allowed` / `previously_used_in_research` fields;
   - order-independent `registry_hash` (XOR of per-game SHA-256 per split + counts + rights snapshot),
     so it is stable regardless of row order and changes if rights change;
   - `assert_no_overlap`, Parquet schema/read/write helpers.
2. **`scripts/rf_build_split.py`** — streaming build from the PR-02 audit Parquet (2.5 M rows),
   `build` and `assert-no-overlap` subcommands, `SPLIT_REGISTRY.md` generation.
3. **`tests/rf_test_split.py`** — 12 tests: L/R boundaries, 2025 H1/H2, 2026 blocked confirm,
   missing month/unknown id, hash-fallback determinism, rights/train_allowed flags, duplicate id
   counting, overlap failure, registry-hash sensitivity, Parquet roundtrip, CLI build + assert,
   fabricated-overlap detection.
4. **`docs/riichiformer/SPLIT_REGISTRY.md`** — frozen counts/hashes, rules, verification, coverage gaps.

## 5. Risks / limitations

- **Canonical/full dedup is not done**: PR-03 is `full_corpus=false` (1,000-game sample). This registry
  relies on Tenhou log-id uniqueness (0 duplicates) and has not computed SHA/canonical equality over
  2.5 M games. A converted copy under a different id would currently be split independently.
- **Rights**: registry includes rights in the hash; all sources `unknown`, so `train_allowed=false`.
  Changing a source to `allowed` changes `registry_hash` and requires a new freeze.
- **No confirmation pool exists**: 2026 is January-only and previously used; `confirm_blocked_previously_used`
  is not a usable confirm set. Any future confirm run needs a new, documented pool.
- `previously_used_in_research=true` for all 2023–2026 rows (544,277); this is conservative and based on
  documented old holdout/EX1 use, not a per-game list.
- Split is per `game_id`; per-POV duplication/sharding is PR-12. Labels are assumed to follow the game.
