## 0. 术语速查（遇到看不懂的词先查这里）

| 词 | 大白话 |
|---|---|
| 半荘 | 一整局麻将（东风战/半庄战），本文里"局"和它同义 |
| 平均顺位 | 4 个人里平均拿第几名。2.5 = 中游，**越小越好** |
| 1v3 duplicate | 评估方法：我们 1 个席位 vs 对手 3 个席位；**同一副牌交换座位各打一遍**，抵消运气和座位优势 |
| 检查点（checkpoint） | 训练中途保存的模型文件，例如 `checkpoints/mortal.pth` |
| 训练步数 | 参数更新一次算"一步"。175.2k = 17.52 万步 |
| GRP | Mortal 里一个小网络，负责预测"这半荘最后会拿第几名"，用来把只在结尾才出现的奖励变得密集 |
| CQL | 一种离线强化学习算法，作用是让模型只敢学数据里出现过的动作，不乱外推 |
| holdout（留出集） | 故意**不参与训练**的数据，专门用来检查模型是"会做题"还是"背了题" |
| 过拟合 | 训练数据上越做越好，但没见过的新数据上不进步 = 背题 |
| seed（种子） | 随机数起点。**固定 seed，两次评估才会用同一批牌局**，结果才能比较 |
| CI（置信区间） | 结果的误差范围。**跨 0 就是"分不出高下"** |
| 统计功效 | 你的尺子能分辨多小的差别。尺子太粗 = 明明进步了也看不出来 |
| ECE | 模型说"我 70% 确定"，实际命中率是否真的 70%？**衡量"自信得准不准"**，越小越好 |
| 消融（ablation） | 一次只改一个零件，和原版对比，看这个零件到底有没有用 |
| anchor（锚） | 一个固定不变的参照模型，给所有实验当标尺（例如 akochan、旧冠军快照） |
| self-play（自对弈） | 模型跟自己的历史版本对打来变强 |
| oracle（上帝视角） | 训练时"偷看"所有牌。**只有训练能用，正式对局不能用** |
| 贪心 / 采样 | 模型每步可以选"分数最高的那个"（贪心）或"按概率抽"（采样） |
| run（一轮） | 用同一个配置、不同随机数训练一次，叫一个 run |

## 2. 第一阶段（第 1–2 周）：先把"尺子"修好

### 1) 评估从 2000 局升到 12000 局 `[我+GLM]`

**为什么做**
你现在的验收是：让新模型和旧模型打 2000 半荘，看平均顺位差多少。问题是**麻将单局的随机性极大**：按你的日志反推，2000 局只能分辨大约 **0.072 名**的差距，而你想检测的进步大约是 **0.05 名**——等于用一把刻度 7 厘米的尺子去量 5 厘米的东西。两份独立报告（我和 GLM）用两套独立数据都算出了同一结论：**2000 局不显著（大约 1.6–1.7 个标准差，属于"可能是运气"）**。

**怎么做**（改 3 行配置）
1. 打开 `configs/config.toml`，找到 `[1v3]` 段：
   - `games_per_iter = 2000` → `games_per_iter = 12000`
   - `seed_key = -1` → 固定值（照 `scripts/eval_akochan.sh` 的做法写 `0x5dfaa4cef265cd7`；`-1` 表示每次都换随机数，成绩不可比）
   - `iters = 1` 保持不变
2. 确认 `[1v3.champion] state_file` 指向固定的旧冠军（现在指向 `mortal.pth.at-148800`，可以）；`[1v3.challenger] state_file` 指向要测的模型（`checkpoints/mortal.pth`）。
3. 跑：
   ```bash
   bash scripts/run_eval.sh configs/config.toml
   ```
4. 看结果：
   ```bash
   python3 scripts/parse_eval.py runs/1v3/eval_*.log
   ```
5. 把"选择用"的 seed 区间和"确认用"的 seed 区间分开记录（比如选择用 `10000–22000`、确认另起一个数段），**确认集只测一次**——这是防止"挑一个好看的数字当结论"的标准做法。

**花多久**：改配置 5 分钟；跑 12000 局约 **1 小时**（实测：2000 局用了 8 分 49 秒，见 `runs/1v3/eval_20260915_1835.log`）。评估和训练可以同时跑，训练会慢 10–15%。

**过关 / 不过关**
- 看结果里 175.2k 与 148.8k 的 95% 置信区间**是否跨过 0**。
- 若跨 0 → 说明"此前 175.2k 比 148.8k 强"**不可判定**，把它记下来，从今往后不要再引用 `+3.08` / `+4.11` 这两个数字。
- 这一步的意义不是"证明谁强"，而是**把尺子校准**：以后所有实验都用这把。

**状态（2026-09-19）**：**已测，结论不可判定**。池 A（`runs/exp/EVAL_A_175200/`）avg_rank 2.476833 CI [2.4599,2.4938]、pt +1.8600 CI [+0.5663,+3.2026]，效应 ≈1.0x 12k MDD；两批独立种子（`runs/variance/pool_2`、`runs/variance/pool_3`）的 CI 都含 parity ⇒ "175.2k 更强"不可判定，`+3.08` / `+4.11` 退役。噪声地板见下一节状态；索引 `docs/EXPERIMENTS.md` E-01/E-02。

### 2) 方差标定：先知道"随机波动"有多大 `[GLM]`

**为什么做**
就算尺子加长到 12000 局，还有另一种噪声：**同一个配置换一个随机数重新训练，结果也会不一样**（run 与 run 之间的差异）。不先量出这个噪声，你无法判断"两个模型 0.02 名的差距"是真实差异还是随机。

**怎么做**
1. 用**完全相同**的配置和检查点，重复 3 次"训练 20k 步"（只改随机种子）。
2. 或者更省事：同一个检查点，用 3 个不同的 seed 区间各评估一遍。
3. 算出这 3 次结果的波动范围（标准差）。
4. 产出一张"最小可辨效应表"：**给定 x 局，能分辨多大的平均顺位差**。

**花多久**：半天。

**过关**：后续任何跨 run 的比较，差距小于这个噪声就写"未证"，不许写成"提升"。

**状态（2026-09-19）**：**已完成**（`runs/variance/`）。合并 σ_set(rank)=0.4678、σ_set(pt)=36.37；**12k 局 80% 功效 MDD ≈ 0.0239 avg_rank / 1.86 pt**（6100 局 0.0336 / 2.61；24000 局 0.0169 / 1.32）；反解 `n≈6.87/Δrank²`、`n≈41525/Δpt²`。另发现评估确定性：池 A 与 pool_1 同 seed 区间时规范化后 12000/12000 逐字节一致（唯 `meta.eval_time_ns` 不同）⇒ 同 seed 重跑是复制，不是独立样本。继承估值 `10.3/Δ²` 比实测保守约 21%。索引 E-02。

### 3) holdout：锁一套卷子当考试题 `[我]`

**为什么做**
现在 `[dataset]` 的 `globs` 是"所有年份的牌谱"（2009–2026 全部），而且 `reserve_ratio = 0.0`。**注意别误会这个参数**：`reserve_ratio` 只是 dataloader 的**缓冲/延后产出**机制——每批文件先缓存 `reserved_size` 组、推迟到后续批次再吐出来（`mortal/dataloader.py:64-78`），本质是节流，跟数据划分无关，设成非零也切不出验证集。真正的问题是：GRP 的验证集是 **2023 年**，但 DQN 训练集**包含 2023**。也就是说：**模型把考试题也背了**。这会导致"训练 loss 一直降，但你不知道它是不是真的更会打牌了"。

**怎么做**
1. 打开 `configs/config.toml` 的 `[dataset]` 段：把 `globs` 从一行 `datasets/extracted/**/*.mjson` 改成**显式的年份列表**，并**排除 2023 年**（这样 2023 同时成为策略和 GRP 的留出年，干净）。
2. **改完 globs 必须删掉 `checkpoints/file_index.pth` 让它重建**（否则它仍指向旧文件集合）。
3. 训练日志里加上"留出年验证 loss"这一项。
4. 顺带确认 2025/2026 年的数据已经规范化过（那两个年份的 `.mjson` 是明文 JSON，必须跑过 `scripts/normalize_gzip.py`，2026-09-14 曾因此崩溃）。

**花多久**：约 1 小时（改配置 + 重建索引 + 一次短训练确认）。

**过关**：能画出"训练 loss 降、验证 loss 不降"的曲线；如果验证集一直没改善 → 抓到过拟合，这本身就是重要信息。

**注意**：这一步只在**重新训练**时生效，不会破坏已有检查点。

**状态（2026-09-17）**：**已完成**（`patches/0005-train-holdout-val-loss.patch`）——`[dataset] globs` 改为显式年份列表（2009–2022），`val_globs` 单列 **2023**，`file_index` 已重建（重建耗时 3.6 s；新索引 0 条 2023 路径）；训练日志/TensorBoard 现有 `holdout_loss`（短训 2000 步实测可见）。另：2024–2026 目前不在任何集合里。（2026-09-19 收尾复核：smoke 产物在 `runs/exp/T7/`，索引 E-03。）

### 5) 两个"几小时"的证伪实验：A1 打乱顺序、A2 线性探针 `[我]`

**为什么要先做这个**
第 8 步（架构改造）和第 10 步（belief 头）加起来要几百小时。而下面这两个实验**各只要几小时**，却能直接判定它们值不值得做。GLM 的规划直接跳到了 belief 头（约 30 小时训练），但**它自己也承认"belief 头可能只是多余的向量"却没有任何检验手段**——这两个实验就是那个检验。

**A1：打乱牌河顺序**
1. 在给模型的输入里，把"牌河"（大家打过的牌）的顺序**打乱**（只乱顺序，不改数量）。
2. 用**同一个模型**、同一批 seed，打 12000 局，和没打乱的结果对比。
3. **判定（注意：这一步容易搞错，本文件初版就写错过一次）**：A1 只能证明"**当前这版权重没用顺序信息**"，**不能**证明"顺序信息没用"——顺序没用起来有三种可能：① 编码没表达好；② 架构提取不出来；③ 对胜率确实没有边际贡献。A1 分不清这三者，必须与 **A9（训练侧打乱历史）** 配对判读：

| | A9 退化 | A9 不变 |
|---|---|---|
| **A1 不变** | 顺序有用、但现有编码/架构没用上 ⇒ **这是支持做序列模型的证据**（Transformer 线的门票，不是死刑判决） | 顺序对"可学到的强度"没有边际贡献 ⇒ 此时才可以考虑关闭该线 |
| **A1 变差** | 顺序已被使用且有用 ⇒ 现有编码够用，Transformer 的增益空间小 | 矛盾 ⇒ 先查实验协议（seed / 分辨率） |

口径：**"不变"必须用 CI 定义**——差异的 95%CI 落在 ±0.05 平均顺位以内才算"不变"，否则"没测出差异"会被误读成"没有差异"。
可选第三臂（同样便宜）：不做打乱，而是把 **recency 衰减平面置零**，直接测"现在是不是靠这个平面在吃顺序信息"。

**A2：线性探针**
1. 把现有模型（175.2k）内部的 1024 维向量"冻结"下来，不再训练它。
2. 在它上面接一个**最简单的线性分类器**（逻辑回归），目标是预测：对手还差几张听牌？我打这张牌会不会放铳？（真值从 oracle 通道拿）
3. 报告 AUC（分辨能力）和 ECE（自信度准不准），对照是"用随机标签"训练同样的分类器。
4. **判定**：如果这个简单分类器**就能解码** → 说明信息早就在向量里了 → **再加一个专门的 belief 头是多余的**，直接砍掉。

**花多久**：A1、A2 各几小时。

**状态（2026-09-19）**：**均已完成**。A1（`runs/exp/A1/`）：shuffle−original Δrank **+0.045833** CI [+0.024000,+0.068917] 排除 0 ⇒ **顺序信息承重**；recency_zero−original Δrank −0.014583 CI [−0.032002,+0.003671] 跨 0（12k 未检出）。A2（`runs/exp/A2/`）：主探针 AUC 0.9334 CI [0.9312,0.9354]，但 24 特征公开基线 0.9399 更高、阳性对照 0.7947 < 0.90 ⇒ `pipeline_valid=false`、`gate_belief=block`。与 A9 配对读 D5 表：顺序在训练与推理两侧都承重；第 8 节架构判决仍关闭了事件 Transformer 分支（见该节状态）。索引 E-08/E-09/E-17。

### 6) 校准审计：不训练，只算指标 `[新]`

**为什么做**
"校准"= 模型说"我 70% 确定"，实际是不是真的 70%。举个大白话例子：一个天气预报员说"今天 70% 下雨"，如果一年里他说 70% 的那些天真的下了 70% 的雨，他就是**校准良好**；如果实际只下了 30%，他就是"嘴硬但没准头"。

已有的三条线索指向同一个猜想：**模型不是学不会（没信号），而是"信号没校准"**：
- 有人试过把 belief 接进搜索，结果**变差**，原因是"搜索会利用 belief 模型的系统性误差"（SuuTTT 战役记录）。
- 三个独立团队的"预测对手手牌"实验都是 null：能预测，但**不涨分**。
- 本领域已经有公开的校准数字可以做对照：Sasaki 的手牌模型 ECE = **0.00188**（扩散）/ **0.000801**（直接预测）；另有一个立直结果模型 ECE = **0.008511**。

**怎么做**（零训练成本）
1. 用 `oracle=true`（在数据管线里能拿到所有人的真实手牌）跑现有模型，采集三组"预测 vs 真值"：
   - A2 探针输出的向听数 / 危险度；
   - **GRP 的 24 种名次排列分布**（`checkpoints/grp.pth`）；
   - Q 值（价值）。
2. 每组画一张"可靠性图"（reliability diagram）：横轴"模型说的概率"，纵轴"实际发生的频率"。完美校准就是一条对角线。
3. 算 ECE / Brier（两个衡量"偏了多少"的数字），并按"模型自信程度"分桶看。

**花多久**：几小时。

**过关 / 不过关**
- 若 ECE 明显差（例如超过 0.05）→ **第 10 步有正当理由**：用校准感知的目标函数去训 belief。
- 若已经很接近公开水平 → **直接关闭 belief 头路线**，把结论写成一篇负结果。

**状态（2026-09-19）**：**已完成**（`runs/exp/A2b/`）。三组 gate-bearing ECE 全部 ≤0.05（A2 探针 0.00987 / GRP top-1 0.02422 / DQN τ=1 0.03643）⇒ triage 门不触发，**ECE 路线同样不给 belief 头开工理由**；与 A2 的 AUC 路线独立一致 ⇒ `gate_belief=block`（`docs/exp-gates.md`）。索引 E-10/E-11。

## 6. 常见问题（Q&A）

**Q1：为什么不直接上 Transformer / 直接开自对弈，非要先做这些"小实验"？**
因为**失败的代价不对称**：A1/A2/校准审计合计不到一天，却分别能证伪"Transformer 有用""belief 头有用""校准是瓶颈"三个假设；而直接训练一个 Transformer + 自对弈是几百小时。先花小钱买信息，再花大钱。

**Q2：12000 局到底跑多久？**
- 对手是**自家模型**（快照/冠军）：约 **1 小时**（实测 2000 局 8 分 49 秒）。
- 对手是 **akochan**：约 **3.4 分钟/局** → 12000 局 ≈ **28 天**，不现实。所以 akochan 只做"趋势尺"（40–100 局），严格对比用自家冠军。

**Q3：改配置会不会弄坏正在跑的训练？**
- 改 `[1v3]`（评估段落）：不会，评估和训练是分开的进程。
- 改 `[dataset] globs`：影响下一次训练；**必须重建 `checkpoints/file_index.pth`**。
- 任何改动前先 `cp configs/config.toml configs/config.toml.bak`。

**Q4：我只有周末，先做哪三件？**
按性价比：**第 1 步（评估扩到 12000）→ 第 5 步（A1/A2 证伪）→ 第 6 步（校准审计）**。做完这三件，你就已经知道后面三周该干什么、不该干什么。

**Q5：校准审计到底看什么数字？**
看两张图/两个数：**可靠性图**（越贴近对角线越好）和 **ECE**（0 最好）。对照基准：Sasaki 麻将手牌模型 0.00188 / 0.000801；立直结果模型 0.008511。如果你的 ECE 比这些差一个量级 → 有改进空间；如果已经接近 → 别做 belief 头了。

**Q6：为什么"动作预测得更准"不能算进步？**
因为已经反复被证明两者会脱钩：SuuTTT 的听牌预测 AUC 0.887（很准）但一局都没多赢；反过来也有"预测不准但打得好"的例子。**打牌的强弱只能用打牌的结果衡量**（平均顺位 + 置信区间）。

## 7. 本轮新增 / 更正的事实（写报告或对外引用时用）

1. **Sasaki 等（dmv.nico，2023-12，非评审）已对麻将手牌/待张概率做过校准研究**：calibration curve + Platt scaling + 加权 ECE = 0.00188（扩散）/ 0.00390（自回归）/ 0.000801（直接预测）→ "麻将 belief 校准无人做过"**不成立**`[S63]`。
2. **hongdp exp69 的辅助头是 3×34 待张多标签**（不是 34×5 手牌计数）：头有效（`aux_sep` 0.44）但对局 A vs P **0.4938±0.0035** = null`[S47]`。
3. **SuuTTT 的 `belief-weighted PIMC` 实测有害**，归因 "search exploits the belief model's systematic errors"`[S46]` —— 这把 belief 头失败的原因从"没信号"改判为"**信号未校准**"，是第 6、10 步的直接依据。
4. 仍未找到"**校准感知目标 + 对局强度验收**"的麻将先例 → 这是第 10 步唯一可辩护的增量。
5. **RUNBOOK 两处与代码不一致**（以代码为准）：① `eval_akochan.sh` 实际默认 **40 局**（RUNBOOK 写 10000 局）；② `[1v3]` 模板注释说"验收时加大"但没给建议值——本文建议 12000。

### A.2 #115 — 折扣"账本"记错行（γ=1 时无害）

**issue 原文**（hyskylord, 2026-02-25）：注释说要对"打牌 + 杠"计折扣，代码却只覆盖 `label <= 37`。

**动作编号**（`libriichi/src/consts.rs:7-15`，46 维；赤 5 定名依 `libriichi/src/tile.rs:12-19`）：`0–33` 普通打牌 ｜ `34–36` **赤 5 打牌（`5mr`/`5pr`/`5sr`）** ｜ `37` 立直 ｜ `38–40` 吃 ｜ `41` 碰 ｜ **`42` 杠宣言** ｜ `43` 和 ｜ `44` 流局 ｜ `45` pass。
**附注**：34–36 **不是**"杠选张"。杠宣言（42）之后"杠哪张"复用 `0–33` 的牌张编号重新置 mask（`at_kan_select` 分支，`libriichi/src/state/obs_repr.rs:423-427`；赤 5 候选在 :431-448 去赤映射后同样走 `0–33`），属于**另一套编码**。

**代码**（`libriichi/src/dataset/gameplay.rs:428-429`）：
```rust
// only discard and kan will discount
self.apply_gamma.push(label <= 37);
```
→ 实际覆盖：打牌 ✓、**赤 5 打牌（34–36）也 ✓（含在 `label <= 37` 里，属误打误撞的正确）**；**立直 ✗（多算）**；漏掉：**杠宣言（42）✗**。

**影响链**：`apply_gamma` → `steps_to_done` → `q_target_mc = gamma ** steps_to_done * kyoku_rewards`（`mortal/train.py:236`）。当前 `[env] gamma = 1`，所以 **1 的任何次方都是 1 → 数值零影响**；一旦做 γ<1 的实验（一个自然的实验），惩罚/折扣就会系统性错位（错 1 格 ≈ 1%，错 10 格 ≈ 10%）。`steps_to_done` 还在别处被拼接复用，属于埋雷。

**未来修法**：改为 `label <= 36 || label == 42`（按注释意图，同时把立直移出）。γ=1 下无差异，属低风险。

**状态（2026-09-17）**：**已修**，落成 `patches/0003-gamma-discount-labels.patch`（标签条件即 `label <= 36 || label == 42`，并把 libriichi 改为 release 构建生效）；γ=1 下行为不变。

### A.3 #111 — 分数编码没有"超车阈值"

**issue 原文**（riking, 2025-12-22）：Mortal 在 all-last 不会接受把自己锁死第 4 的和牌（= A.1 的保险丝），但**构筑阶段**仍会做出"永远追不上"的牌，尤其在"差一点点"时 → 归因于分数输入编码。

**本地代码**（`libriichi/src/state/obs_repr.rs:149-165`）：每个玩家只编码**绝对分数**——
- 平面 1：`clamp(score, 0, 100000) / 100000`
- 平面 2（仅 v4）：`clamp(score, 0, 30000) / 30000` ← **超过 3 万分后饱和**
- （v2/v3 还有 `IntegerEncoder::new(score/100, 500).rbf_intervals(10)`，**v4 反而删掉了这层结构**）

**模型看到 vs 看不到**

| 看到 | 看不到 |
|---|---|
| 4 个绝对分（两种缩放），每行 34 格填同一个数（`fill`） | 我与每个人的**分差**；"还差多少分才能翻盘"；超车阈值 |

**"超车阈值"是什么**：把"差多少分"翻译成"需要多大的牌"时，那套**离散**的分界线。例：我 25000、第 3 名 31600（差 6600）——

| 和牌方式 | 净收入 | 差距缩小 | 够翻盘吗 |
|---|---|---|---|
| 子家 3 翻 30 符 **自摸** | +4000 | ≈5000 | ❌ |
| 子家 3 翻 30 符 **直击第 3 名** | +3900（他 −3900） | ≈7800 | ✅ |
| 子家 満貫 **自摸** | +8000 | ≈10000 | ✅ |
| 子家 満貫 **直击第 3 名** | +8000（他 −8000） | ≈16000 | ✅ |

→ 同一手牌，**直击够、自摸不够**：翻盘线取决于"谁付钱"。且可选分值是一张固定表（1000/2000/3900/8000/12000…）+ 本场 300/供托 1000 的零头 → **是一串离散刻度，不是连续值**。模型必须自己从两个原始分数反推这套逻辑，实测结果是"在临界点出错"。

**未来修法（三档，按代价排序）**

| 档 | 做法 | 是否要重训 | 成本 |
|---|---|---|---|
| **0. 先量化** | 解析 `runs/1v3/*.json.gz` 牌谱，统计 ① all-last 结束时分差分布；② "第 4 名和了但仍是第 4" 的比例（对照带保险丝的基线） | 否 | 几小时 |
| **A. 超车辅助头** | 训练期加辅助任务：从内部表示预测"还需多少分才能超过谁"（标签用规则脚本算，公开信息即可）；输入形状不变 | 否（可热启动微调） | 1 天代码 + 20 万步微调 |
| **B. 加"超车差距"输入平面** | 每个对手一行：`clip((我 − 他)/8000, −2, +2)`，或按离散刻度做分档 one-hot；改 `consts.rs:25`（新增 `5 => (1012+N, 34)`）+ `obs_repr.rs` 的 v5 分支；`model.py:114` 自动跟随；`config.toml` 改 `version = 5` | 是（但可用 **expand-and-zero-init** 热启动：conv1 新通道权重置 0，初始行为与旧模型完全一致） | 1–2 天 + 训练 + 12k 评估 |

**风险提示**：任何走 B 档的方案都会改变输入语义 → 与现有 175.2k 检查点不再严格可比；实验必须设计成"v4（现状）vs v5（阈值编码）"的对照。
