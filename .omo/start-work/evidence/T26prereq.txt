[A] Diagnosis (confirmed — same root cause as T24's evidence [G], not a new one)
  train.py:583-605 collects DataLoader batches whose row count != batch_size into
  `remaining_*`; at the end of the epoch it calls `cat_event_batches(remaining_events)`.
  `collate_events` sizes every batch to THAT batch's own max event length T, so a plain
  torch.cat(dim=0) of tokens/mask needs identical T across leftovers. With the online
  config's `[dataset].num_workers = 3`, each loader worker's shard ends at a different
  point, so every drain tail contains up to 3 short batches; if their T differ the cat
  raises at train.py:591 -> event_data.py:29. Verified on the real run-2 drain set:
  12 full batches (1024 rows) + 3 short batches with T=[150,151,149] (attempt 1 below).

[D] Fix
  `cat_event_batches`: compute the common `seq_len = max T`; zero-pad each shorter
  batch's tokens/mask exactly the way `collate_events` pads (zero tokens, False mask);
  torch.cat the batch-stacked keys; return ONE shared `causal` rebuilt as tril(seq_len)
  (the old code also cat'ed causal along dim 0 whenever it ran, which was already wrong:
  causal is (T,T), not batch-stacked).
  `slice_event_batch`: keep `causal` (T,T) intact and slice only the batch-stacked keys
  (the tail loop at train.py:594-605 slices the concatenated dict into batch_size chunks).

[E] Padding semantics (mandatory check — padding must not influence the model)
  - The padded tail dict is BIT-IDENTICAL to `collate_events` over the same streams, all
    four keys, both synthetic and real (4/4 keys bit-equal in [B] and [C]).
  - mask == (arange(T) < lengths); tokens are zero at every masked position; for every
    unique length l, causal[:l, l:] has no True => no real query can attend a padding key.
  - EventBranch pooled output: real padded tail vs the single unpadded batch is BIT-EQUAL
    (max|d| = 0.0). Synthetic natural-T=149 batch vs the same rows padded to T=150 differs
    only at float-noise level (max|d| = 1.304e-08 < 1e-6). Padding adds no model-visible
    content; the pooled readout still happens at `lengths - 1` (model.py:184).
  - The tail slice loop still yields shape-correct chunks: tokens (1024, T, 5),
    causal (T, T); 539 leftover rows are dropped exactly as the upstream
    `while end <= remaining_bs` loop does (pre-existing behavior, not changed).
