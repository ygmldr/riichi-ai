[G] Fragility found (recorded, NOT fixed here — todo 26 owns the real run)
-------------------------------------------------------------------------------------
Run 2's trainer crashed in the online tail-batch path:
  File "vendor/mortal/mortal/train.py", line 591, in train_epoch
    events = cat_event_batches(remaining_events)
  File "vendor/mortal/mortal/event_data.py", line 29, in cat_event_batches
    return {k: torch.cat([b[k] for b in batches], dim=0) for k in keys}
  RuntimeError: Sizes of tensors must match except in dimension 0. Expected size 149 but got size 150
    for tensor number 1 in the list.
Cause: each DataLoader batch's event `tokens`/`mask`/`causal` are sized to that batch's own max event
  length (collate_events: seq_len = lengths.max()). The online tail path concatenates the leftover
  sub-batch dicts along dim 0, which requires identical seq_len across them; two leftover batches with
  different max lengths (149 vs 150) abort the epoch. Run 1 happened to have all tail batches share a
  length and completed cleanly (no traceback; ended at 37 steps + param submit). This is a pre-existing
  vendor limitation in the online path, not introduced by this todo; it is a real risk for todo 26's
  long A14 run and should be handled there (e.g. pad tail event batches to a common seq_len before cat).
  Not fixed here per MUST-NOT (no vendor change beyond patch 0009; A14 training is todo 26).
